**Releases.** Tagging `v*` triggers `.github/workflows/release.yml`, which forwards to the shared `release-bun.yml@a9ecff42ac7721452905327071316bca2b49bb68` reusable workflow in `yasyf/homebrew-tap`: a per-target `bun build --compile` on four native runners (macOS + Linux, arm64 + x86_64 — OpenTUI's per-platform native packages rule out cross-compiling), a `--version` smoke on every leg, a GitHub release with the four zipped binaries, and the Homebrew cask rendered from the repo-owned `.github/formula/cc-pane.rb.tmpl` (tokens `__VERSION__` + the four `__SHA_*__`; it declares `depends_on` on the `cc-orchestrate` cask and the `cc-notes` formula) pushed to the tap. The bun toolchain is pinned by `.bun-version`; the binary's `--version` compiles in `package.json`'s `version` — bump it in the release commit alongside the tag. The release refuses a tag not on `main` — tag a merged commit (e.g. `git tag vX.Y.Z origin/main`). A hyphenated tag (`v0.1.0-rc.1`) publishes a prerelease and skips the cask — the dry-run channel. macOS binaries must be Developer-ID-signed and notarized; the shared workflow fails before packaging unless all five `MACOS_*` secrets are present. `HOMEBREW_TAP_TOKEN` is required for the cask push.
